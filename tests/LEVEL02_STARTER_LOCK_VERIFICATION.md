## 实际行为

初始同时显示分开放置的中件和顶件。中件沿导槽侧推，就位后保留原样，顶件才成为可操作件。玩家再向下拖动顶件，使其同时嵌住中件上口和固定座梁。中件单独就位不算完成，也不会自动跳过第二次操作。

A/B/C 选择不同中件，并在选材时配好相应顶件。A 的窄上口配窄卡齿，B 的偏移上口配同样偏移的顶件，C 保留原配套形状。三组都能落到底并卡住，顶件激活、下压及同排重复过程中不会变形或更换成 C。选材阶段可更换整套木料，中件入座后固定配对。

同排另一处依次演示中件侧推、顶件下落，并保留同一 A/B/C 的两个实体。此处扣合自身完整，但该榫型不提供连续船板接收边：下一块可以观察和浅推，提交装入后才因实际缺边而报组装失败。已有扣合保持原样，下一块不会被记作已安装。

中件未完成锁合时可返回船架、重进观察或取回中件。不会因此丢失中间状态或增加已装数量。沿用原观察界面，没有新增预览模式或场景文字标记。

## 实现边界

- `starter_lock.gd` 接受本套接收体的局部几何数据及上口偏移，生成配套顶件；不读取状态或判定。B 的槽口与顶件共用 `boat_joints.gd.middle_upper_offset()` 的 `.30` 偏移，卡齿实际进入可见上口。`convex_carving.gd` 负责凸体裁切，生成连续木料的实际网格；槽口向下开放，生成后按安装位置和开口缓存。
- `hull_view.gd` 管理待装顶件、已就位中件和接触姿态；全部路径检查包含固定船架及真实已装件。`level_state.gd` 保存局部中间状态，`level02.gd` 协调两次操作和重复动作。
- 配套这一轮修改视图、顶件生成器及共享槽位参数提取；状态、协调器、UI、`starter_joint.gd`、`ship_geometry.gd`、灯光/木材外观及接收边模块保持原样。共享参数提取不改变后续正式扣合撑几何；企口和搭扣的模型与动作不变。

## 验证

[执行与源文件索引](evidence/starter-matched-20261108/verification-summary.json)记录配套版本的结果和隔离副本摘要。GPU 使用 `/private/tmp/guchuan-starter-matched-review`，未操作用户现有 Godot 窗口。

- `starter_lock_geometry_tests`：两处位置 × A/B/C 顶件完整下降路径，逐段独立三角面/包含检查；六组均无穿透落座，卡齿占据可见上口中心。中件在无顶件时可退出，有顶件时不能退出；顶件不能与中件一起滑出固定座梁，落位后有实际承托，裁切木料仍连通。反证测试保留：将 C 顶件错配给 A/B 仍会受阻，证明是实际几何配套而非跳过碰撞。
- `starter_lock_tests`：实际鼠标拖动，包括配套顶件在初始已出现、激活前后形状不变、浅推不提交、两次手动装入、选择锁定、返回重进、取回中件、ABC 全部完成、自动件保留原配对并分别走两段动作。每组均继续试装下一块，浅推不报错，提交才因缺少实际接收边失败。
- 回归通过：首处其他榫型、错型接触、整关正确输入、实际接收边及船用搭扣/扣合几何。B 最终位置调整后另重跑完整配套几何与 GPU 输入。

过程发现：配套初版 B 虽能限制退出，但卡齿没有正对可见上口；现让顶件跟随该槽位偏移，并增加上口中心占位检查。调整拖动取点时一处变量名错误导致临时检查失败，修复后重新通过。历史失败日志保留，不计入最终通过结果。上一轮单一 C 顶件的证据仍在 [旧执行记录](evidence/starter-lock-20261108/verification-summary.json)，不代表当前规则。
