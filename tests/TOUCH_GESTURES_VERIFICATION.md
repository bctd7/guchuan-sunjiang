# 第一、二关触屏手势（2026-11-09）

本轮把双指捏合接入第一、二关的观察装配区、榫型/尺寸候选模型和共享放大窗。目标机器已知为 Windows，分辨率与多点能力未知。实现与自动验证完成；尚未在目标触摸屏或 Windows 导出包上实测。

| 操作 | 当前行为 |
|---|---|
| 单指轻点候选 | 选择该木料，轻微抖动不转动模型 |
| 单指拖候选／观察区空白 | 旋转该区域的相机 |
| 单指抓木料沿箭头推入 | 延续已有浅推、抽回和松手提交规则 |
| 同一区域双指分开／合拢 | 放大／缩小；沿用已有缩放范围和重置按钮 |
| 拖木料时加入第二指 | 停在实际浅推位置，不提交装配；全部抬手后可重新抓住继续 |
| 双指跨不同卡片、第三指加入 | 暂停该轮操作，不误选材、不误装配 |
| 缩放中一指离开 | 剩余手指不变成新的旋转或拖装，全部抬手后再开始 |
| 放大窗返回、窗口尺寸改变、失焦 | 清理旧手势，下一次按下可正常操作 |

第二关 A/B/C 捏合时保持共同显示比例，接收件参照同步。两指缩放由原始触点位置的距离比计算，与鼠标滚轮共用现有相机缩放入口。GUI 实际收到按下事件的区域才认领触点，遮挡后的页面不能跟着缩放。跨出当前模型区域后仍由起手区域接续，抬手后释放所有权。

打开放大窗前清理后台接触点并保留浅推位置，解决禁用后台输入期间漏接抬手、返回后拖不动的问题。鼠标模拟重复事件继续被过滤。触摸抖动容差使用 10 个逻辑像素；鼠标保持原阈值。

## 自动验证

新夹具 `tests/touch_gesture_tests.gd` 注入真实 Viewport ScreenTouch/ScreenDrag 事件，不直接调用生产输入回调。覆盖两关、1440×900 与 960×600、另一次窗口尺寸切换、候选同比例、主视图与放大窗、浅推转双指及重新拖装、跨卡片/第三指、区域外抬手、系统取消、模拟失焦、鼠标重复事件，以及最后一次实际装配提交。

- 最终 headless：150 通过，0 失败。
- 最终 Mac GPU：164 通过，0 失败；后台最小化、不抢焦点，保留 12 张画面。
- 原有回归：`level01_orbit_tests`、`level02_drag_tests`、`opening_navigation_tests`、`drag_consistency_tests`、`inspection_workspace_tests` 通过。覆盖鼠标/单指、不同尺寸与缩放、正确和错误装配的原流程。
- 运行器将脚本、解析和引擎错误视作失败。沙箱中的系统证书读取和编辑器设置保存警告单独记录，不视作产品功能通过的证据。

最终报告与源文件散列见 [验证汇总](evidence/touch-gestures-20261109/verification-summary.json)，独立的 [headless 报告](evidence/touch-gestures-20261109/headless.json) 与 [GPU 报告](evidence/touch-gestures-20261109/gpu.json) 保留原始输出。图片位于同一目录；原报告中的 `res://tests/evidence/touch-gestures/` 是隔离副本运行时的输出路径。

## Windows 实机待核对

1. 在独立游戏窗口／全屏下，确认系统确实能同时提供两个触点。若只提供单点或鼠标模拟，继续使用现有缩放按钮。
2. 第一、二关各做一次选材、拖空白旋转、双指缩放和实际拖装；保持木料浅推时加第二指，全部抬手后再继续，确认没有误提交。
3. 放大候选、缩放、返回，确认第一次单指操作就能响应；切换应用再回来，确认没有卡住的触点。
4. 按验收机实际分辨率与 Windows 显示缩放检查按钮、底栏及文字。当前仍为整页等比缩放，本轮没有增加最小字号或窄屏重排。

第三关及旧独立课堂没有在此轮统一接入双指。Mac GPU 与模拟事件不代表 Windows 驱动、多点硬件或全部页面已通过实机验收。
