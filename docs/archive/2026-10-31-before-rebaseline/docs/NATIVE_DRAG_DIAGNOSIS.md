# 真实窗口拖动核查与选型入口修复

本轮没有改变吸附阈值、拖动算法、模型或装配规则。

## 实际窗口核查

已通过 Windows Computer Use 在用户当前 Godot 嵌入调试窗口操作，未调用游戏内部方法代替鼠标。

1. 进入现场时木料 A 已选中，上方榫型没有选中，「准备试装」为禁用状态。这个状态不能安装，但旧提示只说尚未选择，未明确缺少榫型。
2. 实际点击「半榫」和木料 C，抓住船肋弯曲实木处，沿箭头方向拖动后松手；成功进入安装回看，动画结束时船肋已接到龙骨。
3. 返回骨架，自动装配正常开始；用撤回取回本次测试组，恢复用户未装配进度。
4. 在观察页空白处实际拖动，视角正常旋转。随后恢复默认视角与原先仅选木料 A 的状态。

因此这次没有复现「类型和长度已选齐后仍不能拖动」。不能据此声称用户遇到的所有拖动失败都已排除。

正式工程脚本哈希与上轮合入一致；运行实例也在合入后启动，已排除旧进程未更新。当前嵌入窗口能够用原生鼠标完成以上操作，未发现此次路径存在缩放坐标偏差。

## 对照原实现

原教学拖动位于 `core/interaction.gd`、`core/guided_drag.gd` 和 `core/orbit_camera.gd`，采用物理射线拾取、固定手势 mode、入口捕获后沿路径插入。观察页采用独立显示克隆和 GUI 覆盖层，使用真实三角面拾取及从起点到终点的投影路径。本轮实测这条链可完成安装，故未在缺少故障证据时替换算法或扩大范围。

## 本轮界面修复

代码确认旧榫型卡片只有底部文字按钮可选，图片不响应选择；现整张卡片（含模型图）均可选。选择仅木料时明确提示「木料 A 已选好，再点上方挑一个榫头」；缺项按钮解释下一步，不默认选答案或直接安装。

页面改为简短游戏引导，移除「教学连接设计，非历史复原」「尚未选型参考」等反复说明；保留实际尺寸、观察槽口和拖动方法。

后台补充回归：模型图片区域真实 GUI 点击、缺项按钮不安装、选择保持与重置；实际 GPU 验证新界面及后续拖入。它们和上面的原生鼠标记录分别报告，不混为人工测试。

## 授权与限制

第一次读取聊天窗口授权超时，未执行切回；用户确认卡片后重试已返回 ChatGPT 窗口状态。没有绕过确认或修改用户聊天内容。游戏测试已撤回到原进度；没有强制关闭用户编辑器。

本轮未实测实体触屏，也未实测其他分辨率或用户的另一条失败手势。若仍失败，需记录具体点击的卡片、抓取位置、拖动方向及松手时页面状态，才能进一步定位。
